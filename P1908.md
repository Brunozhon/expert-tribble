# Inversions

This is a very classic problem that you can solve by modifying a classic merge sort algorithm.

In conventional merge sort, you split a list into one-element segments, and then merge the segments together by finding the lesser of the first elements of each segment, removing it from its segment, and adding it to a bigger segment consisting of all of the elements of the two smaller elements until the whole list is sorted.

How can this be used to count the number of inversions in a list? If the right element is less than the left element, you add the remaining amount of elements of the left segment to the answer, the number of inversions. Consider this simple list:

```c++
[3, 1, 4, 2]
```

First, we split the list into four segments.

```c++
[3], [1], [4], [2]
```

Then, we check the first two elements. Since three is greater than one, we count one inversion.

```c++
[1, 3], [4], [2]
inversions = 1
```

Then, we check the last two elements. Since four is greater than two, we count one more inversion.

```c++
[1, 3], [2, 4]
inversions = 2
```

Now, we get to sorting the two two-element segments. We start on the first elements of each segment.

```c++
[1, 3], [2, 4]
 ↑       ↑
```

Since one is less than two, we advance the first arrow, add one to the final array, and do not count an inversion. (You can also remove the first element, as explained above.)

```c++
[1, 3], [2, 4]
    ↑    ↑
final = [1]
```

Since three is greater than two, we count an inversion.

```c++
[1, 3], [2, 4]
    ↑       ↑
final = [1, 2]
inversions = 3
```

Finally, since three is less than four, we do not count an inversion. This gives us a final answer of three inversions.

```c++
[1, 2, 3, 4]
inversions = 3
```

Ignoring the cat-and-mouse backstory that references the popular TV show *Tom and Jerry*, this problem is basically a counting-inversions problem. Even without complex topics like binary index trees, I still managed to pass under the problem's stringent one-second time limit after a few tries.

```c++
#include <cstring>
#include <iostream>

// This function takes in a pair of segments. For the purposes of this
// explanation, the segment [l, r) will be referred to as the "left segment,"
// and the segment [r, e) will be referred to as the "right segment." You can
// probably guess what the letters stand for.
long long merge(long long a[], long long b[], long long l, long long r, long long e) {
    // The current offset into the left segment.
    long long i = l;
    // The current offset into the right segment.
    long long j = r;
    // The number of inversions gained by merging the left and right segments
    // together.
    long long ans = 0;

    // Iterate over the final destination of the left and right segments.
    for (long long k = l; k < e; k++) {
        // Checks if the left array is in bounds. If it is, checks whether the
        // right array is out of bounds or the current element of the left
        // segment is less than the current element in the right segment.
        if (i < r && (j >= e || a[i] <= a[j])) {
            // If the condition is satisfied, we do not count an inversion and
            // advance the left segment, inserting the current element into
            // the combined segment.
            b[k] = a[i];
            i++;
        } else {
            // Otherwise, the remaining length of the left segment will be added
            // to the inversion count and we advance the right segment, inserting
            // the current element into the combined segment.
            ans += r - i;
            b[k] = a[j];
            j++;
        }
    }

    // Returns the number of inversions. Adding inversions to a global variable
    // would've allowed me to save a couple of instructions, but I'm not sure
    // if the -O2 flag set by the compiler turns ans into one big global variable.
    return ans;
}

// Many competitive programmers would use signed main() here along with #define
// int long long, but I just prefer to use my IDE's find-and-replace function
// and replace this one instance of long long with int.
int main() {
    // Get array and array length from standard input. Similarly to how I do not
    // like to use #define int long long, I also prefer adding std:: to every
    // standard library function instead of adding using namespace std; because
    // it opens up a few more variable names that the C++ standard library
    // takes up, like min and max.
    long long n;
    std::cin >> n;
    long long a[n];
    for (long long i = 0; i < n; i++) {
        std::cin >> a[i];
    }

    // A variable to store the answer.
    long long ans = 0;

    // Temporary variable used by merge sort.
    long long b[n];

    // Merge sort works by splitting the array up and then merging it together,
    // as described above. w iterates through all the widths of the resulting
    // segments, starting from merging all of the small one-element segments
    // to merging the two big segments that form the complete, sorted list.
    for (long long w = 1; w < n; w <<= 1) {
        // Iterate through every pair of segment. If there is an odd number of
        // segments, the last segment passed to merge() will be empty.
        for (long long i = 0; i < n; i = i + (w << 1)) {
            // Merge the two segments together.
            ans += merge(a, b, i, std::min(i + w, n), std::min(i + 2 * w, n));
        }

        // Copy the results stored in b to a for use in the next iteration.
        std::memcpy(a, b, n * sizeof(long long));
    }

    // Outputs the answer. If a return value is not specified by the main()
    // function, it defaults to being zero, allowing me to save a line of code.
    std::cout << ans;
}
```
